# PREREG: Compound v3 (Comet) `buyCollateral` discounts, as a slower liquidation-adjacent venue (candidate #100, "more venues" lever) — written 2026-11-22 before any Comet data

Question: after Compound v3 "absorbs" an underwater account, the collateral sits in the protocol and anyone may buy it at a discount to the oracle price with `buyCollateral`; the opportunity lasts until someone buys it, so it need not be a same-block oracle-update race like Aave/Morpho. Does the bonus (collateral value − base amount paid) pass the registered bars on the chains where our free endpoints have deep history (Base, Arbitrum, Optimism, Polygon)?
Stage 0 (desk, third-party/assumed): `buyCollateral(asset, minAmount, baseAmount, recipient)` is permissionless; the discount is the store-front price factor (protocol parameter, not re-read here); competition and bot count unknown; Malaysia/legal unverified; five-part filter as for Aave. The profit is NOT a liquidation fee: absorbing itself (the liquidation call) earns the caller only gas, so a bot's income is the discount on the collateral it buys, then sells.
Data: `BuyCollateral(address indexed buyer, address indexed asset, uint256 baseAmount, uint256 collateralAmount)` logs, topic-only (every Comet contract is discovered, no address list assumed); base token per contract from `baseToken()`; receipts for gas/winner; DefiLlama prices; decimals via `decimals()` with DefiLlama fallback. Bonus (gross) = collateralAmount × price(asset) − baseAmount × price(base token) at DefiLlama daily prices; events with missing price or bonus/collateral outside [−2%, +30%] excluded and counted. Winner = tx `from`. Gas only; selling the collateral (slippage) is unobserved, so income is an upper bound.
Stage 1 pilot (KILL-ONLY): last 3 months (2026-08-01..2026-10-31) per chain; a chain whose total pilot gross < USD 3,750 is dropped. Stage 2: 24 months (H1 = months 0–11, H2 = 12–23); a VENUE (chain, Comet contract) passes only if in both halves (a) top-3 winners hold < 60% of gross bonus, (b) a bonus event in every month, (c) net bonus outside the top 3 averages >= USD 500 a month, 20-event minimum per half; the same `venue_stats` code. A pass is again not proof that a new bot would win (speed/competition untested); a replay-type test would follow separately if one venue passes.
Output: `scripts/liq_comet_20261122.py` → `docs/jx_runs/liq_comet_20261122.txt` (run twice, identical), ledger rows, CANDIDATES #100 update.

## Addendum 1 (2026-11-22, stage-2 results seen for Base and Arbitrum; written before the timing data below): results and a timing test
Stage-2 result (command `uv run python -I scripts/liq_comet_20261122.py full`): NO venue passes the registered test (rules not changed). Near misses: Base USDC Comet 0xb125e6…: H1 gross $1.87M, top-3 0.41, every month, outside-top-3 net $88.5K/month pooled; H2 gross $0.58M, top-3 0.40, outside-top-3 net $27.2K/month, but a bonus event in only 11 of 12 months (fails (b)). Arbitrum USDC Comet 0x9c4e…: H1 top-3 0.602 and 11 of 12 months, H2 passes. Pilots killed: Optimism, Polygon. So the money exists (about $2.4M in 24 months for the Base USDC Comet alone, top-3 about 0.40, about 100 winners a half-year) but the registered bars are not met.
Question that decides whether it is a SLOW niche or the same same-block race: do the buys happen in the same transaction as the `AbsorbCollateral` (a bot absorbing and buying atomically, i.e. an oracle-triggered race) or separately? Timing test (descriptive, no pass/fail, cannot change the registered Comet result): for the largest-gross venue on Base and on Arbitrum, a deterministic sample of up to 300 buy transactions; fetch each receipt; record whether the receipt contains an `AbsorbCollateral(address,address,address,uint256,uint256)` log from the same Comet, and the number of `BuyCollateral` logs. Reading: if more than 70% of buy transactions also absorb, the venue is an atomic race and joins the same-block group; if under 30% the buying is separate and slower (a niche worth a dedicated timing replay); in between mixed. Output `docs/jx_runs/liq_comet_timing_20261122.txt`, ledger rows.

Note (2026-11-22): the first timing run picked the venue by summed raw base-token units, which mixes decimals and chose small venues (Base 0x784efe…, Arbitrum 0x6f7d51…: 36% and 61% of sampled buys also absorb). That is not the registered "largest-gross venue".
